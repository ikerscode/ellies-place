# Wave 1 contracts review

Reviewer: code-reviewer#1, Wave 1, Tue 13 Oct 2026. Read only: no source, spec or test was changed. Probes ran from the session scratchpad, not in the repo.

Question asked: can the 13 Wave 2 agents (engine, sim, world and build, save, ui, audio, art A to D, writer, data, qa) build in parallel against these contracts without colliding or guessing?

Read: `FROZEN.md`, `contracts.md`, `TECH.md`, `PROMPT.md` (Wave 2 table), every `.claude/agents/*.md`, all of `src/core/` (`types.ts` in full, 3250 lines), every module `index.ts`, `tests/unit/core/`, `scripts/lint.mjs`, `tests/soak/run.ts`, and sim.md, home.md, play.md, ui.md, audio.md, art.md, voice.md against them.

Baseline: `npm run typecheck` 0 errors. `npm run lint` OK (58 files). `npm test` 23 files, 164 tests pass. `npm run soak` exits 0 and prints "stub OK" (it hashes the RNG and simulates nothing).

## Verdict: NOT READY

6 block, 41 fix, 13 nit.

The shared helpers (RNG, hash, geometry, rules, state skeleton) are sound and tested, and every item in FROZEN §4 is present in `types.ts`. The trouble is at the seams: the world cannot reach the sim, engine or cats; three specs name the same sprites, strings and activity outcomes differently; one helper still contradicts FROZEN #17; and two Wave 2 agents are both told to write the soak runner. Each blocker is a small, mostly additive change. With B1 to B6 landed this becomes READY WITH FIXES, and the F rows can be fixed by their owners during Wave 2.

## 0. Rules for every artist

- **Item key:** `item.<ItemId>` (rotation 0), `.r1` (facing left, side view), `.r2` (facing up, back view). Rotation 3 is `.r1` flipped by the engine, so you never draw it. Then `.on`, `.open`, `.full`, `.overhead` for states. Rotation comes before state: `item.record_player.r1.on`.
- **Orientations (home.md column):** `4` = keys base, `.r1`, `.r2`; `2` = base and `.r1`; `1` = base only.
- **State keys exist per rotation.** `front` states (`.open`, and `.on` on screens, stoves and the treadmill) are not drawn for `.r2` (back view): the engine falls back to the plain `.r2` key. `all` states are drawn for every rotation.
- **Sizes** are the grid in px before the compiler adds the 1 px outline (compiled size is +2 × +2). Floor items: width `16 × fw − 2`; r0 height is the target; for `.r1` the footprint swaps and the height becomes `h + 16 × (fw − fh)`. Treat heights as a target within ±4 px, and keep the front edge on the footprint bottom. Rugs, mats and patterns are 16 px per tile, no outline.
- **Base and recolour:** `base#palette` in `home.md` means one grid recoloured. Draw the row marked **draw**, then make each row marked **recolour of** with `recolor()` and a palette swap (and tweak details only if it needs them). Recolours share size, rotations and states with their base.
- **Palette, outline, light:** as `design/spec/art.md` §1 to §4: `PAL` colours only, top-left light, neon only on Neon-tagged items, lavender rim (`ink.rim`) on black or near-black subjects.
- **Status column:** `done` = already in `src/art/base/` and passing the registry tests; `partial` = a first version exists and the note says what is missing; `proposed` = not in the old `art.md` list, added because a sim.md interaction needs it; `todo`.
- **MVP flag** is the catalog flag for items. For non-item sprites it is the art lead's judgement from sim.md Scope columns: `Y` means an MVP interaction or screen shows it.
- **Counts:** a **key** is one registry entry; **frames** counts the drawn pixel grids behind it (directions × frames; left is a free flip, rotation 3 is a free flip).

Batches: **A** characters and animations (`src/art/base/`), **B** bedroom, living and lighting, **C** kitchen, bathroom, gym and props, **D** garden, plants, cat furniture, patterns, motifs, icons and fx. Folders `src/art/b/`, `c/`, `d/`.

## Notes, proposals and open points

- **P1 (pattern variants):** `PaintPattern` has six names but the paints need seven more looks (`carpet`, `rubber`, `herringbone`, `hex`, `flags`, `brick`, `band`). Proposal: `PaintDef` gets an optional `variant?: string` and the engine looks up `pattern.<surface>.<variant ?? pattern>`. Until the architect decides, the data owner may point `PaintDef.pattern` at the closest base name and the sprite key list stays as above.
- **P2 (icon key family):** the checklist uses `icon.int.<glyph>` (contracts.md and ui.md) rather than `icon.<interactionId>`: interaction ids contain dots and share glyphs, so one key per id would be about 90 icons; this plan draws 21 new glyphs and reuses 40 existing icon keys.
- **P3 (states beyond the frozen four):** `item.front_mailbox.on` means flag up (mail waiting); `gym_medal_rack` has no state keys (medals are overlaid from `icon.medal.*`); `prop.vase.broken` and `prop.box.open` are prop keys, outside the item state rule.
- **P4 (lot structure tiles):** walls, doors, windows, the archway, hedge, fence and the garden wall are not in this list. `art.md` has no key family for them. If the engine does not draw them procedurally, the lead adds an `env.*` family and a batch D section.
- **P5 (new Ellie and cat anims):** `ellie.hold_cat`, `ellie.wand`, `cat.<n>.lap` (George, Salem, Peaches, Bruce excluded), `cat.<n>.scratch`, `cat.<n>.play` and `prop.sled` are added because MVP interactions in sim.md need them and `art.md` did not list them.
- **P6 (fallbacks):** the checklist assumes the atlas falls back from a missing state key or `.r2` state to the plain key, as `art.md` §4 does for missing directions. The architect should confirm `itemSpriteKey` plus `atlas.has` do this.
